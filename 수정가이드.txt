0. 매우 중요 - 이제 js/calc.js를 직접 고치면 안 됩니다
====================================================
이 사이트는 "하루 3번 자동으로 세율을 확인해서 업데이트"되도록 만들어져 있습니다.
그 구조상 js/calc.js는 이제 사람이 손으로 고치는 파일이 아니라,
data/rates.json 값을 바탕으로 scripts/generate-calc.mjs가 자동으로
"찍어내는" 결과물입니다.

→ 세율/보험료율을 고치고 싶으면 js/calc.js가 아니라 data/rates.json을 고치세요.
→ data/rates.json을 고친 뒤에는 아래 명령을 실행해서 js/calc.js를 다시 생성해야
  변경 내용이 실제 사이트에 반영됩니다. (Node.js 설치 필요, nodejs.org에서 설치)

    node scripts/generate-calc.mjs

  로컬에 Node.js를 깔기 귀찮다면, data/rates.json만 고쳐서 GitHub에 올려도 됩니다.
  다음 자동 실행(하루 3번 중 한 번) 때 js/calc.js도 함께 갱신되어 커밋됩니다.

1. 이 사이트가 "완전 자동으로 업데이트"되는 원리
====================================================
.github/workflows/check-rates.yml 에 등록된 GitHub Actions가 하루 3번
(07:00 / 13:00 / 19:00, 한국시간) 자동으로 scripts/check-rates.mjs 를 실행합니다.

  (1) 국민연금 보험료율 → 법으로 이미 정해진 인상 스케줄을 날짜 계산으로 확인
      (2025.3 국민연금법 개정: 2026년 9.5%에서 매년 0.5%p씩 인상해 2033년 13%까지 인상)
  (2) 국민연금 기준소득월액 상한/하한액, 건강보험료율, 장기요양보험료율
      → 보건복지부/국민연금공단 공식 페이지 텍스트를 읽어서 확인 (스크래핑)
  (3) 고용보험료율(근로자 부담) → 4대사회보험 정보연계센터(4insure.or.kr, 정부
      공동 운영 포털)의 "실업급여" 항목 텍스트를 읽어서 확인
  (4) 종합소득세 세율표(제55조), 근로소득공제 구간(제47조), 근로소득세액공제
      한도(제59조) → 국가법령정보센터 법령 원문을 그대로 옮겨 싣는 casenote.kr
      에서 조문 원문 문장("1,400만원을 초과하는 금액의 15퍼센트" 등)을 그대로
      읽어서 파싱합니다. 이 3가지는 숫자 하나만 잘못 읽어도 전체 계산 결과가
      틀어질 수 있어서, 파싱한 표가 내부적으로 앞뒤가 맞는지(구간이 끊기지
      않는지, 금액이 이어지는지 등) 별도로 한 번 더 검증한 뒤에만 반영합니다.
      셋 중 하나라도 검증에 실패하면 그 항목은 통째로 건드리지 않고 넘어갑니다.

  ※ 이번 자동화 작업 중 기존 계산 로직의 실제 버그 2개를 발견해서 함께 고쳤습니다.
    - 근로소득공제는 법적으로 2,000만원을 넘을 수 없는데, 예전 코드엔 이 상한이
      빠져 있어서 총급여가 아주 높은 경우 공제가 과다 계산되고 있었습니다.
    - 근로소득세액공제 한도표는 원래 4단계(~3,300만/~7,000만/~1.2억/1.2억 초과)인데,
      예전 코드엔 3단계까지만 있고 마지막 "1.2억원 초과 시 한도가 20만원까지
      더 낮아지는" 구간이 통째로 빠져 있었습니다.
    두 버그 모두 총급여 상위 구간(대략 1.2억원 이상)에서만 실수령액이 아주
    조금 낮게(더 정확하게) 바뀌는 정도라 대부분의 이용자에게는 체감되지 않습니다.

값이 바뀐 것을 발견하면, data/rates.json과 js/calc.js를 자동으로 고치고
**곧바로 main 브랜치에 커밋 & 푸시**합니다. (별도의 승인/병합 절차 없음.
GitHub Pages나 Netlify가 main 브랜치를 보고 있다면 몇 분 안에 실제 사이트에도
반영됩니다.)

  ※ 안전장치: 정부 사이트 구조가 바뀌어 스크립트가 이상한 숫자를 읽어올
    가능성에 대비해, "상식적인 범위/변동폭을 벗어난 값"은 자동으로 버리고
    적용하지 않습니다 (scripts/check-rates.mjs의 validate 함수). 이런 경우
    아래 2번 항목의 Error_log 파일에 기록만 되고, 잘못된 숫자가 사이트에
    올라가지는 않습니다.

2. 문제가 생기면 어디서 확인하나요? (Error_log_날짜.txt)
====================================================
스크립트가 정부 사이트에서 값을 못 읽어오거나, 읽어온 값이 이상하다고
판단해서 버렸을 경우, 프로젝트 루트에 다음과 같은 파일이 자동으로 생깁니다.

    Error_log_2026-08-26.txt

파일 안에는 어떤 항목에서 무슨 문제가 있었는지, 왜 그런지 적혀 있습니다.
이 파일이 새로 생기거나 내용이 늘어났다면, 정부 사이트의 문구/구조가 바뀌었을
가능성이 큽니다 → scripts/check-rates.mjs 안의 정규식 패턴이나
data/rates.json의 source 링크를 최신 페이지에 맞게 손봐야 합니다.

(참고: GitHub 저장소의 "Actions" 탭 → 개별 실행 기록 → Summary 에서도
매번 실행 결과를 확인할 수 있습니다. Error_log 파일은 그중 "문제가 있었던
경우"만 프로젝트 폴더 안에 남기는 것입니다.)


====================================================
3. GitHub Actions 설정 - "Actions 메뉴가 안 보여요"에 대한 답
====================================================
개인 계정 설정 화면(오른쪽 위 내 프로필 사진 → Settings, 주소가
github.com/settings/... 로 시작)에는 원래 "Actions" 메뉴가 없습니다.
그 화면은 계정 전체 설정(이름, 이메일, 비밀번호 등)이고, Actions 설정은
"저장소(repository) 하나하나마다" 따로 있습니다.

Actions 설정을 보려면:
  1) 상단에서 본인이 만든 저장소로 들어가세요.
     주소창에 직접 입력해도 됩니다: github.com/본인아이디/저장소이름
  2) 그 저장소 페이지 안의 탭 (Code / Issues / Pull requests / Actions / Settings...)
     중에서 저장소 전용 "Settings" 탭을 클릭하세요. (개인 계정 Settings와는
     완전히 다른 화면입니다.)
  3) 왼쪽 메뉴에서 "Actions" → "General" 클릭
  4) 맨 아래 "Workflow permissions" 에서
       - "Read and write permissions" 선택
       - Save
     (main 브랜치에 자동으로 커밋/푸시하려면 이 권한이 반드시 필요합니다.
      이 설정을 안 하면 check-rates.yml은 실행은 되지만 마지막 push 단계에서
      권한 오류로 실패합니다 - Actions 탭 → 실행 기록에서 빨간 X로 표시됩니다.)

  ※ 저장소를 처음 만들고 코드를 한 번도 push하지 않았다면 "Actions" 탭
    자체가 비어 있거나 안 보일 수 있습니다. 8번 항목대로 먼저 GitHub에
    코드를 올리세요.

4. 절대 비용이 나오지 않게 하는 방법 (중요)
====================================================
과거에 GitHub 사용료가 크게 나온 적이 있으시다니, 이 프로젝트는 아래 원칙으로
만들었고, 추가로 계정 설정에서 한 번 더 막아두는 것을 강력히 권장합니다.

  (1) 저장소를 반드시 "Public"으로 만드세요.
      Public 저장소는 GitHub Actions 표준 러너(ubuntu-latest) 사용 시간이
      완전히 무제한 무료입니다. (Private 저장소는 매달 2,000분 무료 제공 후
      초과 시 과금됩니다. 이 프로젝트는 하루 3번, 1회 1분 내외라 한 달에
      100분 정도밖에 안 쓰지만, 그래도 Public이 안전합니다. 어차피 GitHub
      Pages 무료 호스팅도 Public 저장소 기준으로 설계된 가이드입니다.)

  (2) [가장 확실한 방법] GitHub 결제 한도를 0원으로 고정하세요.
      우측 상단 프로필 사진 → Settings → 왼쪽 메뉴 "Billing and licensing"
      → "Plans and usage" (또는 "Spending limit") 항목에서 추가 사용량에
      대한 지출 한도(Spending limit)를 "$0" 로 설정하세요.
      이렇게 해두면 만에 하나 무료 한도를 넘는 사용량이 발생해도 GitHub가
      자동으로 그 초과분 실행을 막아버릴 뿐, 카드에 청구되지 않습니다.
      (이건 이 프로젝트뿐 아니라 계정 전체에 적용되는 가장 강력한 안전장치입니다.)

  (3) 이 워크플로(.github/workflows/check-rates.yml) 자체에도 안전장치를
      넣어뒀습니다: 실행 시간이 5분을 넘으면 자동으로 강제 종료(timeout-minutes)
      되고, 이전 실행이 안 끝났으면 겹쳐서 실행되지 않습니다(concurrency).
      외부 유료 API도 전혀 사용하지 않습니다 (정부 공식 페이지를 그냥 읽기만 함).

5. 매년/수시로 사람이 직접 확인해야 하는 것 (자동화가 커버 못 하는 부분)
====================================================
이제 4대보험료율, 종합소득세 세율표, 근로소득공제, 근로소득세액공제까지
전부 자동으로 확인·반영됩니다. 사람이 할 일은 사실상 아래 한 가지뿐입니다.

- Error_log_날짜.txt 파일이 새로 생기거나 계속 쌓이는지 가끔 확인하세요.
  (2번 항목 참고) 이 파일이 있다는 건 "이번엔 자동으로 못 고쳤으니 확인이
  필요하다"는 신호입니다. 대개 casenote.kr/4insure.or.kr/정부 사이트의
  페이지 문구가 바뀌어서 정규식이 더 이상 안 맞는 경우입니다.

- 아주 드물게, 세법 자체의 "계산 방식"이 바뀌는 경우(예: 근로소득공제
  구간의 개수 자체가 늘어나거나, 근로소득세액공제 산식의 배율(1/2, 8/1000
  같은 분수)이 바뀌는 경우)는 자동화가 구조 변경까지는 따라가지 못할 수
  있습니다. 이런 큰 개정은 매우 드물게 일어나고(수년~10년 단위), 뉴스에도
  크게 보도되니 그런 소식을 보면 scripts/check-rates.mjs와 data/rates.json을
  한 번 열어서 확인해보세요.

====================================================
5-1. 퇴직금 / 육아휴직급여 / 재산세 계산기 - 자동확인 대상 아님 (직접 관리 필요)
====================================================
이 3개 계산기는 연봉 계산기와 달리 하루 3번 자동 확인 시스템(check-rates.mjs)에
포함되어 있지 않습니다. 아래 파일들의 숫자를 직접 확인하고, 바뀌면 직접 수정해야
합니다.

- 퇴직금 계산기 (js/retirementCalc.js)
  → 계산 공식 자체가 근로기준법에 고정되어 있어(평균임금×30일×재직일수/365)
    거의 바뀌지 않습니다. 사실상 신경 쓸 필요가 없습니다.

- 육아휴직급여 계산기 (js/parentalLeaveCalc.js)
  → 상한액(월 250만/200만/160만원)·하한액(월 70만원)·지급률(100%/80%)이
    정부 정책 개정으로 종종 바뀝니다. "육아휴직급여 상한액" 뉴스가 보이면
    이 파일 맨 위 monthlyTierFor 함수의 숫자를 직접 고치세요.

- 재산세 계산기 (js/propertyTaxCalc.js)
  → 공정시장가액비율(1세대1주택 43~45%, 그 외 60%)과 세율표는 정부가 매년
    부동산 대책 발표 때 바꾸는 경우가 있습니다. "공정시장가액비율 발표"
    "재산세 개편" 같은 뉴스가 보이면 이 파일 위쪽의 PROPERTY_STANDARD_BRACKETS,
    PROPERTY_SPECIAL_BRACKETS, fairMarketRatioFor 함수를 직접 고치세요.

세 파일 모두 js/calc.js와 달리 자동 생성 파일이 아니라 "직접 수정하는" 일반
파일입니다. 고친 뒤 바로 git add/commit/push 하면 됩니다 (별도 생성 스크립트
실행 필요 없음).

6. GitHub 사용자명 / 사이트 주소 반영
====================================================
이 저장소는 이름을 "smilemaskl.github.io" 로 지어서, GitHub Pages가 사이트를
루트 주소(https://smilemaskl.github.io/, 뒤에 아무 경로 없이)에서 서비스해줍니다.
(저장소 이름이 정확히 "아이디.github.io" 형태이면 GitHub이 자동으로 루트 주소를
내려줍니다. 네이버 서치어드바이저처럼 "호스트 단위" 주소만 받는 곳에 등록하려면
이 방식이 필수입니다.)

robots.txt / sitemap.xml 안의 주소는 이미 https://smilemaskl.github.io/ 기준으로
맞춰뒀습니다. 만약 GitHub 아이디가 다르거나 저장소 이름을 다르게(예: 그냥
salary-calculator) 만들었다면:
- 저장소 이름이 "아이디.github.io" 가 아니면 사이트는 https://아이디.github.io/저장소이름/
  형태의 하위 경로로 서비스됩니다. 이 경우 robots.txt/sitemap.xml의 모든 주소
  뒤에 "/저장소이름/"을 다시 붙여야 하고, 네이버 서치어드바이저 등록 시
  "호스트 단위 URL" 오류가 날 수 있습니다 (10번 항목 참고).

9. 새 계산기 추가하는 방법
====================================================
현재 연봉 실수령액(salary.html) · 퇴직금(retirement.html) · 육아휴직급여
(parental.html) · 재산세(propertyTax.html) 4개가 만들어져 있습니다. retirement.html
이나 propertyTax.html을 열어보면 "계산 로직 파일(js/xxxCalc.js) + 화면 입출력
파일(js/xxx.js) + html 페이지" 3개가 한 세트로 구성된 걸 볼 수 있는데, 새 계산기를
추가할 때도 이 구조를 그대로 따라 하면 됩니다.

1) 가장 비슷한 기존 html 파일을 복사해서 이름 변경 (예: 4대보험 계산기라면
   salary.html 복사)
2) 안의 입력 항목(라벨, input)을 새 계산기에 맞게 수정
3) js 폴더에 새 계산 로직 파일 + 화면 입출력 파일 작성 (예: fourInsuranceCalc.js,
   fourInsurance.js)
4) index.html의 <div class="card-list"> 안에 새 카드(<a class="calc-card"
   href="...">) 추가
5) sitemap.xml에도 새 페이지 주소 한 줄 추가
6) 7번 항목대로 <head>에 애드센스 주석도 넣어두기

10. GitHub에 올리고 배포하는 방법 (무료)
====================================================
[GitHub Pages로 배포]
1) github.com 에서 새 저장소(Repository) 생성. 이름을 정확히
   "본인아이디.github.io" 로 지으면(예: smilemaskl.github.io) GitHub Pages가
   자동으로 사이트를 루트 주소(하위 경로 없이)에서 서비스해줍니다. 반드시 Public.
2) 이 폴더(salary-calculator) 내용을 저장소에 push
   (터미널 예시)
     git init
     git add .
     git commit -m "계산기 모음 최초 배포"
     git branch -M main
     git remote add origin https://github.com/본인아이디/본인아이디.github.io.git
     git push -u origin main
3) 저장소 Settings > Pages 메뉴에서
   Source를 "Deploy from a branch", Branch를 "main / (root)"로 선택 후 저장
4) 몇 분 뒤 https://본인아이디.github.io/ 로 접속 확인 (경로 없이 루트 주소)
5) 3번, 4번 항목의 Workflow permissions / Spending limit 설정을 꼭 해두세요.

※ 저장소를 이미 다른 이름(예: salary-calculator)으로 만들어서 운영 중이라면,
  저장소 Settings 맨 위 "Repository name" 칸에서 이름을 "본인아이디.github.io"로
  바꾸기(Rename)만 해도 같은 효과를 볼 수 있습니다. 이름을 바꾸면:
  - 사이트 주소가 https://본인아이디.github.io/저장소이름/ 에서
    https://본인아이디.github.io/ (경로 없이) 로 바뀝니다.
  - 로컬 git remote 주소도 새 이름으로 바꿔줘야 합니다:
      git remote set-url origin https://github.com/본인아이디/본인아이디.github.io.git
  - 구글 서치콘솔에 예전 주소(.../저장소이름/)로 등록했다면, 새 루트 주소로
    속성을 다시 추가하고 소유확인을 다시 해야 합니다 (예전 속성은 지워도 되고
    안 지워도 상관없습니다).
  - 네이버 서치어드바이저는 애초에 하위 경로 주소를 등록할 수 없기 때문에
    (11번 항목 참고) 이 방식으로 루트 주소를 만들어야만 등록이 가능합니다.

[또는 Netlify로 배포]
1) netlify.com 가입 후 "Add new site" > "Import an existing project"
2) 위에서 만든 GitHub 저장소 선택 (빌드 명령 없음, Publish directory는 "/")
3) 배포 완료 후 자동으로 무료 서브도메인(예: xxxx.netlify.app) 생성됨
   (매일 3번의 자동 요율 확인/커밋은 GitHub Actions 기능이므로, Netlify는
   그냥 GitHub 저장소가 바뀔 때마다 재배포만 해주는 역할입니다. 자동 커밋이
   main에 올라가면 Netlify가 알아서 재배포합니다.)
